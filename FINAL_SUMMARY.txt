PROJECT: Curling Timer X for Rabbit R1
ISSUE: PTT button activating voice assistant while app is active
STATUS: ✅ COMPLETE AND READY FOR DEPLOYMENT

================================================================================
PROBLEM STATEMENT
================================================================================

When using the Curling Timer X app on the Rabbit R1 device, pressing the PTT
(Push-to-Talk) button would:
  1. Start/stop the timer (✅ DESIRED)
  2. Activate the voice assistant (❌ UNDESIRED)

This caused interruptions and unwanted voice assistant interactions while users
were trying to use the timer.

================================================================================
SOLUTION IMPLEMENTED
================================================================================

A comprehensive two-layer approach:

LAYER 1: MANIFEST-LEVEL PTT LOCKING
  • File: .rabbit/manifest.json
  • Added: "lockPtt": true
  • Effect: System-level PTT locking when app is active

LAYER 2: APPLICATION-LEVEL EVENT CAPTURE
  • File: apps/app/src/lib/ptt-handler.js
  • Features:
    - Event capture in capturing phase
    - stopPropagation() on PTT events
    - Automatic visibility management
    - Focus state tracking
    - Comprehensive logging

HOW IT WORKS
================================================================================

EVENT FLOW (BEFORE):
  PTT Button Press
    → longPressStart event fires
    → Timer captures event (Timer starts ✅)
    → Event propagates to system
    → Voice assistant activates ❌

EVENT FLOW (AFTER):
  PTT Button Press
    → longPressStart event fires
    → PTT Handler captures in capturing phase
    → stopPropagation() / stopImmediatePropagation()
    → Timer receives event (Timer starts ✅)
    → Event does NOT propagate to system
    → Voice assistant does NOT activate ✅

VISIBILITY MANAGEMENT:
  • App Active → PTT Locked → Voice Assistant Disabled
  • App Hidden → PTT Unlocked → Voice Assistant Available
  • App Returns → PTT Locked → Voice Assistant Disabled
